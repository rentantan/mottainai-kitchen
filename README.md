# もったいないキッチン（Mottainai Kitchen）

大学生の一人暮らしを想定した、賞味・消費期限管理と節約レシピ提案のWebアプリです。

## アプリのコンセプト

**食費を抑えたい、料理に時間をかけられない、食材を余らせたくない。** そんな一人暮らしの学生を助けます。

- レシピは必ず1人分
- 1食の予算を300円・500円・700円から選択
- 調理時間を10分・20分・30分から選択
- 冷蔵庫にある食材を優先し、期限が近い食材をさらに優先
- 買い足し食材を少なくし、初心者でも作れる料理を提案
- 期限切れの登録食材はレシピに使わないよう指示
- フライパン・鍋・電子レンジ程度で作れる料理を優先

## Gemini APIについて

レシピ提案には Gemini Developer API の `gemini-3.5-flash-lite` を使います。アプリから食材名・数量・単位・期限・予算・調理時間をバックエンドへ送り、Geminiが日本語のレシピ候補、1人分の材料、分量、手順、材料費の概算を生成します。

**これはGoogle検索で既存のレシピサイトを検索する機能ではありません。** Geminiが条件に合わせてレシピ案を生成します。無料枠で使えるテキスト生成を優先するため、Google検索グラウンディングは使用していません。したがってレシピ出典URLは付きません。

### 無料利用と注意点

- Googleの料金ページでは、`gemini-3.5-flash-lite` のStandard利用に無料枠が表示されています（2026年11月3日確認）。ただし無料枠・モデル提供状況・リクエスト上限は変更される可能性があります。
- 無料枠だけを使う場合、Google AI StudioでAPIキーを作成し、課金アカウントはリンクしないでください。有料化や支払い情報を求められた場合は手続きを止め、APIキーなしのサンプルモードを使ってください。
- 無料枠の入力・出力内容はGoogleのサービス改善に利用される場合があります。登録食材・期限情報がGoogleへ送信されることを理解したうえで利用してください。メモ欄はGeminiへ送信しません。
- Google AI Studioの画面に表示される自分のプロジェクトの上限を確認してください。無料枠のリクエスト数は一律に保証されません。
- 予期しない連続呼び出しを避けるため、成功した提案はSQLiteに24時間保存します。同じ食材・予算・時間ではキャッシュを返し、Gemini APIを呼びません。起動時のみ自動提案し、食材追加や設定変更のたびに自動呼び出しはしません。新規のAPI呼び出しはアプリ側でも20秒間隔・1時間5回・1日8回までに制限しています。必要なら `backend/.env` で調整できます。
- Geminiが返す材料費は概算です。実際の価格は地域・店舗・購入量で変わります。

公式情報：

- [Gemini API 料金](https://ai.google.dev/gemini-api/docs/pricing)
- [Gemini API レート制限](https://ai.google.dev/gemini-api/docs/rate-limits)

## 無料で使うための構成

| 部分            | 技術                                        |     料金 |
| --------------- | ------------------------------------------- | -------: |
| フロントエンド  | React + TypeScript + Vite                   |     無料 |
| バックエンド    | Python + FastAPI                            |     無料 |
| AIレシピ提案    | Gemini Developer API Free Tier              | 無料枠内 |

## 必要なもの

- macOS / Windows / Linux
- Node.js（LTS推奨）
- Python 3.10以上
- Googleアカウント（Gemini APIを使う場合）

## 起動方法（macOS）

ターミナルを2つ開きます。

### 1. Gemini APIキーを設定（任意）

1. [Google AI StudioのAPIキー画面](https://aistudio.google.com/apikey)を開き、APIキーを作成します。
2. `backend/.env.example` を `backend/.env` にコピーします。
3. `backend/.env` の `GEMINI_API_KEY=` にキーを設定します。
4. `GEMINI_MODEL=gemini-3.5-flash-lite` はそのままにしてください。高ボリューム向けの軽量モデルで、テキスト入出力に無料枠があります。
5. 課金アカウントはリンクしないでください。AI Studioで無料枠を使えない表示になった場合は、APIキーを設定せずサンプルモードで利用してください。

```bash
cd backend
cp .env.example .env
# .envをエディタで開き、GEMINI_API_KEYを設定
```

### 2. FastAPIを起動

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

APIの状態は http://localhost:8000/api/health 、APIドキュメントは http://localhost:8000/docs で確認できます。`geminiConfigured` が `true` ならAPIキーを読み込めています（キー自体は表示されません）。

### 3. Reactを起動

別のターミナルで実行します。

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

ブラウザで http://localhost:5173 を開きます。

- 食材の追加・編集・削除
- 食材名、数量、単位、カテゴリ、期限、メモの管理
- 期限切れ・今日まで・明日まで・期限間近の表示
- 食材の検索、カテゴリ絞り込み、期限状態フィルター
- 食材を使ったときの数量減算／使い切り
- Gemini APIによる節約レシピ提案（1人分）
- 1食の予算・調理時間の切り替え
- 期限が近い食材を優先した候補の並べ替え
- 材料の分量、作り方、材料費の概算表示
- APIキー未設定・無料枠超過・通信障害時のローカルレシピ切替
- Gemini APIキーをバックエンドだけで管理（ブラウザへ送らない）
- Gemini成功レシピをSQLiteへ24時間キャッシュ（再起動後も再利用）

- メールアドレス・パスワードによる新規登録、ログイン、ログアウト
- ログインセッション（30日間）の保持と認証APIによる冷蔵庫データ操作の保護
- 食材、使い切り数、レシピ提案キャッシュをログインユーザーごとに分離

## データ保存（SQLite）

食材データと使い切り数は、バックエンドのSQLiteデータベース `backend/data/mottainai.db` に保存します。SQLiteは1つのファイルで動作するため、PostgreSQLのようなDBサーバーや外部サービスへの登録は不要です。Python標準ライブラリの `sqlite3` を使っているため、追加パッケージも必要ありません。

- 食材の追加・編集・削除・消費はFastAPI経由でSQLiteへ保存します。
- 初回起動時、以前のバージョンの `localStorage` に食材があればSQLiteへ自動移行します。既存データがなければサンプル食材を登録します。
- `localStorage` はSQLiteに接続できない場合のローカル動作とキャッシュ用に残しています。画面下部に現在の保存先を表示します。
- ブラウザを変えても、同じFastAPIバックエンドにつながれば同じSQLiteデータを参照します。別のPCで使うには、そのPCから同じバックエンドに接続できる必要があります。
- SQLiteファイルはバックエンドを実行しているPCに保存されます。バックアップする場合はFastAPIを停止してから `backend/data/mottainai.db` をコピーしてください。
- `DATABASE_PATH` 環境変数で保存先を変更できます。公開サーバーで使う場合は、再起動・再デプロイ後も残る永続ストレージを指定してください。

ログインユーザーごとに食材・使い切り数・レシピ提案キャッシュを分離して保存します。未ログインのAPI操作は拒否され、認証セッションは30日間有効です。

## バックエンドの構成

`backend/main.py` はFastAPIの設定とルーター登録を担当します。認証は `auth.py`、食材CRUDは `pantry.py`、レシピ提案とGemini連携は `recipes.py`、SQLite操作と認証共通処理は `database.py`、Pydanticモデルは `models.py`、環境設定は `config.py` に分かれています。

フロントエンドも、`App.tsx` を画面状態とレイアウトの中心にし、認証画面・食材入力モーダル・レシピ詳細モーダルを `src/components/`、型を `types.ts`、初期データと定数を `data.ts`、日付計算やレシピ評価を `utils.ts` に分けています。

Reactの表示はTSX、全体の見た目はCSSで管理しています。CSSはReactと役割が競合せず、レスポンシブ対応や共通スタイルをまとめやすいため、無理にスタイルまでTSXへ移行せずCSSを継続します。HTMLは`index.html`とTSXのJSXに限定しています。

## SQLiteからPostgreSQLへ移行する場合

個人開発・ローカル利用ではSQLiteを推奨します。利用者が増えたり、複数ユーザーが同時に書き込む公開サービスへ発展させる段階でPostgreSQLを検討します。現状の実装はSQLite専用で、PostgreSQLへは接続設定だけで切り替わりません。移行時にはDBアクセス層をSQLAlchemy等へ統一し、スキーマ移行とデータ移行を行う想定です。

Gemini APIを使う場合、レシピを考えるために食材名・数量・単位・期限・予算・調理時間をGoogleへ送信します。メモ、ユーザー名、メールアドレスは送信しません。APIキーはFastAPIの環境変数にだけ保存し、フロントエンドの `.env` やソースコードに書かないでください。

## 無料公開について

最初はローカルで開発すれば、ホスティングサービスへの登録や支払いは不要です。インターネット上に公開する場合は、無料ホスティングの永続ストレージ条件を必ず確認してください。

**Render FreeにはSQLiteを置かないでください。** Renderの無料Web Serviceはエフェメラルファイルシステムで、再起動・スリープ・再デプロイでSQLiteファイルが失われます。また、Renderの無料PostgreSQLも作成から30日で期限切れになります。データを長期保存したい場合、無料枠だからという理由だけでRender Freeを選ぶのは避けてください。公式説明：[Render Free](https://render.com/docs/free)。

公開時はAPIキーをフロントエンドに設定せず、必ずバックエンドの環境変数に設定してください。公開サーバーのAPIキーを他人に使われないよう、認証や利用制限も検討してください。

## 食品安全について

賞味期限・消費期限だけで食品の安全性を完全に判断することはできません。保存方法や開封状態も確認し、異臭・変色・ぬめり等の異常があれば食べないでください。肉・魚・卵は十分に加熱してください。アプリのAI提案は食品安全の専門的な判定ではありません。

## Gemini API の HTTP 503 エラー

HTTP 503 は、Gemini API 側が一時的に混雑・容量不足になっているときに返るエラーです。APIキーの間違いを示す401/403や、利用上限を示す429とは異なります。

この版では、503を受け取るとバックエンドが指数バックオフ（約1秒・2秒・4秒、少しランダムな待ち時間を追加）で最大3回自動再試行します。それでも失敗した場合は、アプリ内の節約レシピを表示し、画面の「もう一度提案」から手動で再試行できます。短時間に何度も押さず、少し待ってから再試行してください。

Gemini APIの状態は[Google AI Studioのステータス](https://aistudio.google.com/status)で確認できます。

## Geminiモデル・キャッシュの変更（v2.3）

この版では `gemini-3.5-flash-lite` を標準モデルにしています。Google公式ドキュメントでは高ボリューム向けの軽量モデルと説明され、Standardのテキスト入出力はFree Tierで無料です。ただし、あなたのGoogleプロジェクトに適用される正確なRPM・TPM・RPDはAI Studioでモデルを選んで確認してください。別モデルに変えても無料枠の上限が必ず増える保証はありません。

- 成功したAIレシピはSQLiteの `recipe_suggestion_cache` テーブルに24時間保存します。
- 同じ食材・期限・予算・時間・日付・モデルなら、キャッシュを返すためGemini APIを呼びません。
- 日付が変わると期限までの日数が変わるため、キャッシュキーも更新します。
- キャッシュはバックエンド再起動後も残ります。SQLite DBを削除するとキャッシュも削除されます。
- 起動時に1回提案し、その後はユーザーが「条件を反映して提案」を押したときだけAPIを呼びます。食材を1つ追加するたびに自動でAPIを呼び出すことはありません。
- `.env` の `GEMINI_MAX_REQUESTS_PER_DAY=8` などでアプリ側の保護上限を変更できます。これはGoogle側の上限を増やすものではありません。

既存環境でモデルを切り替える場合は、`backend/.env` の `GEMINI_MODEL=gemini-3.5-flash-lite` に変更してFastAPIを再起動してください。`.env.example` を更新しただけでは、既に存在する `.env` は自動変更されません。
