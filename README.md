# もったいないキッチン（Mottainai Kitchen）

大学生の一人暮らしを想定した、**食材の期限管理**と**節約レシピ提案**のWebアプリです。
冷蔵庫の食材を登録しておくと、期限が近いものから使える1人分のレシピを Gemini API が提案します。

> 食費を抑えたい、料理に時間をかけられない、食材を余らせたくない ── そんな一人暮らしの学生向けです。

## 主な機能

### 🧊 冷蔵庫（食材管理）

- 食材の追加・編集・削除（食材名・数量・単位・カテゴリ・期限・値段（任意）・メモ）
- はじめは空の冷蔵庫から開始。「サンプルで試してみる」でサンプル食材を入れ、「すべて削除」で空に戻せる
- **冷凍保存**：期限が近い肉・ごはん・パン・野菜などを ❄️ ボタンで「冷凍」にすると期限の目安を約1か月に延長（解凍すると期限は翌日に）。冷凍中の食材はGeminiにも「解凍が必要」と伝える
- 食材名を入れると、よくある単位・カテゴリ・絵文字・期限の目安を自動入力（手で直した項目は上書きしない）。期限は「今日／明日／3日後／1週間後／2週間後」からワンタップでも選べる
- 「期限切れ」「今日まで」「明日まで」「期限間近」の表示と、期限3日以内の食材の通知
- 食材名検索、カテゴリ絞り込み、期限状態フィルター（期限間近・期限切れ）
- 「使った！」で数量を減らす（1単位・半分・全部・任意の量）。0になると使い切りとしてカウント。通知の「元に戻す」で取り消せる（レシピの「作った！」も同様）
- 削除時に「捨てた」か「登録ミスなどで削除」かを選択。削除後の通知の「元に戻す」で取り消せる
- **もったいない記録**：「捨てた」食材を記録し、今月捨てた品数と金額（値段を登録した食材は、残っていた量の割合で換算）・これまでの品数・今月の使い切り率（今月使い切った品数÷(使い切り＋捨てた)、これまでの率も併記）・最近捨てた食材を表示。同じ食材を繰り返し捨てているとヒントを表示
- サンプル食材の投入と「すべて削除」。どちらも使い切り数ともったいない記録は残す（「すべて削除」では、記録もリセットするかを確認）

### 🍳 レシピ提案

- Gemini APIによる**1人分**の節約レシピを3つ提案
- 1食の予算（300円／500円／700円）と調理時間（10分／20分／30分）を選択
- **「電子レンジだけ」モード**：コンロがない・使えない部屋向けに、電子レンジ（と電気ケトル・炊飯器）だけで作れるレシピに限定
- 期限が近い食材を使うレシピを上位に並べ替え、期限切れの食材は材料に使わない
- 食材名の表記ゆれを吸収して在庫と照合（「鶏もも肉」と「鶏肉」、「ネギ」と「ねぎ」、「醤油」と「しょうゆ」、全角・半角、「卵(Mサイズ)」「キャベツ1/2」など）。名前の一部が同じだけの別の食材（「ねぎ」と「玉ねぎ」、「油」と「醤油」、「酢」と「ポン酢」など）は区別する
- 材料の分量・作り方・材料費の概算を表示
- 「作った！」で使った食材をまとめて冷蔵庫から減らす（分量はレシピから推測し、編集可能）
- 常備調味料の登録（登録した調味料は買い足しに数えず、Geminiにも伝える）
- **保存したレシピ**：気に入ったレシピをレシピ詳細の「このレシピを保存」で保存（最大50件、同じ名前は上書き）。AIの提案回数を使わずに何度でも開けて、表示のたびに今の冷蔵庫の中身と照合し直し、期限が近い食材を使えるもの・買い足しが少ないものから並べる。「保存済み」を押すと外せる（通知の「元に戻す」で取り消し可）
- APIキー未設定・利用上限・通信障害時は、アプリ内の節約レシピ（14種類、うち電子レンジだけで作れるもの3種類）に自動で切り替え

### 🛒 買い物リスト

- レシピの買い足し食材をワンタップで追加
- 購入後に「冷蔵庫へ」で食材登録（登録するとチェック済みになる）
- 同じ食材の別表記（「ネギ」と「長ねぎ」、「醤油」と「しょうゆ」など）は重複して追加しない
- チェック済み項目の一括削除

### 👤 アカウント・その他

- メールアドレス＋パスワード（8文字以上）での新規登録・ログイン・ログアウト
- ログインの総当たり対策：同じメールアドレス＋同じ接続元で5回、同じメールアドレスで計20回、同じ接続元で計50回失敗すると15分間ロック。他人がメールアドレスを入力するだけで本人を締め出すことはできない。新規登録は接続元ごとに1時間20件まで
- アカウント設定（右上のメニュー）：パスワード変更（ほかの端末はログアウト）、ほかの端末からのログアウト、アカウントと全データの削除
- ログインセッションは30日間有効。食材・買い物リスト・常備調味料・レシピキャッシュはユーザーごとに分離
- ログイン期限切れ時はログイン画面へ戻る
- サーバーに接続できないときは前回の内容を読み取り専用で表示（「再接続」で復帰）
- スマートフォン向けレイアウト（下部タブバー、カード型の食材リスト）
- Escキーでモーダル・メニューを閉じる。メニューは外側をクリックしても閉じる。モーダル表示中はTabキーのフォーカスがモーダル内にとどまる
- 日付が変わると期限の残り日数を自動で更新（開いたままにしても、バックグラウンドから戻っても）
- スマートフォンのホーム画面に追加可能（Webアプリマニフェスト・アイコン対応）

## クイックスタート

### 必要なもの

- Node.js（LTS推奨）
- Python 3.10以上
- Googleアカウント（Gemini APIを使う場合のみ）

ターミナルを2つ使います（バックエンド用・フロントエンド用）。

### 1. バックエンド（FastAPI）

```bash
cd backend
cp .env.example .env          # 必要なら GEMINI_API_KEY を設定（下記）
python3 -m venv .venv
source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

起動確認：

- http://localhost:8000/api/health … `geminiConfigured` が `true` ならAPIキーを読み込めています（キー自体は表示されません）
- http://localhost:8000/docs … APIドキュメント

### 2. フロントエンド（React）

別のターミナルで実行します。

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

ブラウザで http://localhost:5173 を開き、新規登録してから使います。

### 3. Gemini APIキーの設定（任意）

1. [Google AI StudioのAPIキー画面](https://aistudio.google.com/apikey)でAPIキーを作成します。
2. `backend/.env` の `GEMINI_API_KEY=` にキーを設定します。
3. FastAPIを再起動します。

> [!IMPORTANT]
> - APIキーは **`backend/.env` にだけ**書いてください。`frontend/.env` やソースコードには書かないでください。
> - 無料枠だけで使う場合は、Google AI Studioで**課金アカウントをリンクしないでください**。支払い情報を求められたら手続きを止め、APIキーなしで利用してください。

## Gemini APIによるレシピ提案

### しくみ

フロントエンドから食材と条件をバックエンドへ送り、バックエンドが Gemini API を呼び出します。Geminiは日本語のレシピ候補・1人分の材料と分量・手順・材料費の概算をJSONで返します。

**Google検索で既存のレシピサイトを探す機能ではありません。** Geminiが条件に合わせてレシピ案を生成します（Google検索グラウンディングは使っていないため、出典URLは付きません）。

プロンプトで指示している主な条件：

- 必ず1人分、料理初心者でも作れる内容
- 選択した予算・調理時間以内（守れないレシピはバックエンド側でも除外）
- フライパン・鍋・電子レンジ程度で作れる
- 登録食材を優先し、期限が近いものほど優先。期限切れの食材は使わない
- 買い足しは原則2種類以内
- 肉・魚・卵は十分に加熱する

### Googleへ送信するデータ

| 送信する | 送信しない |
| --- | --- |
| 食材名・数量・単位・カテゴリ・期限、常備調味料、予算、調理時間 | メモ、メールアドレス、パスワード |

無料枠の入力・出力内容はGoogleのサービス改善に利用される場合があります。理解したうえで利用してください。

### 無料枠を使いすぎないための工夫

- **在庫はサーバー側で参照**：提案にはSQLiteに保存された冷蔵庫の中身を使います（ブラウザから在庫は送りません）。ほかの端末で編集した直後でも、最新の在庫で照合されます。
- **キャッシュ**：成功した提案はSQLiteの `recipe_suggestion_cache` テーブルに24時間保存します（最新100件まで、再起動後も有効）。同じユーザー・食材（名前・数量・単位・期限）・常備調味料・予算・時間・日付・モデルなら、Gemini APIを呼ばずにキャッシュを返します。日付が変わると期限までの日数が変わるため、別の提案になります。
- **自動呼び出しは起動時の1回だけ**：その後は「別のレシピを提案」／「新しい条件で提案」ボタンを押したときだけ呼び出します。食材や条件を変えるたびに自動で呼ぶことはありません。
- **「別のレシピを提案」**：条件が同じでもキャッシュを使わずにGeminiを呼び出し、いま表示している料理とは別のものを提案させます（新しい結果でキャッシュを上書き）。アプリ内レシピの場合も、まだ表示していないレシピを優先します。
- **アプリ側の呼び出し制限**：アプリ全体で1日8回、アカウントごとに1日4回・1時間3回・20秒間隔。1人が使い切っても他のユーザーは使えます。Gemini呼び出しが失敗した回はアカウントの回数に数えません（アプリ全体の回数には数えます）。上限に達するとアプリ内レシピを表示します。値は[環境変数](#環境変数)で変更できますが、Google側の上限が増えるわけではありません。

### 料金・無料枠の注意

- Googleの料金ページでは、`gemini-3.5-flash-lite` のStandard利用に無料枠が表示されています（2026年11月3日確認）。無料枠・モデル提供状況・上限は変更される可能性があります。
- 自分のプロジェクトに適用される正確な上限（RPM・TPM・RPD）は、Google AI Studioでモデルを選んで確認してください。別モデルに変えても上限が増える保証はありません。
- Geminiが返す材料費は概算です。実際の価格は地域・店舗・購入量で変わります。

公式情報：
[料金](https://ai.google.dev/gemini-api/docs/pricing) ／
[レート制限](https://ai.google.dev/gemini-api/docs/rate-limits) ／
[APIキーの取得](https://aistudio.google.com/apikey) ／
[テキスト生成](https://ai.google.dev/gemini-api/docs/text-generation)

## データ保存（SQLite）

すべてのデータはバックエンドのSQLiteファイル `backend/data/mottainai.db` に保存します。1ファイルで動くため、DBサーバーや外部サービスへの登録は不要です。

テーブル構成はバージョン管理しています（SQLiteの `PRAGMA user_version`）。起動時に `backend/database.py` の `MIGRATIONS` のうち未適用のものだけを順に実行し、途中で失敗したらその変更はすべて取り消します。構成を変えるときは `MIGRATIONS` の末尾に関数を追加してください（既存の関数は書き換えない）。アプリより新しいバージョンのDBでは起動を止めます。

| テーブル | 内容 |
| --- | --- |
| `users` / `auth_sessions` | アカウント（パスワードはPBKDF2でハッシュ化）とログインセッション |
| `pantry_items` / `app_state` | 食材（冷凍の有無・値段を含む）と使い切り数 |
| `waste_log` | 「捨てた」食材の記録（もったいない記録。金額換算を含む） |
| `consume_log` | 「使った」の記録（取り消しと今月の使い切り率に使用） |
| `shopping_items` / `pantry_staples` | 買い物リストと常備調味料 |
| `saved_recipes` | 保存したレシピ（冷蔵庫と照合する前のレシピ本体をJSONで保存） |
| `recipe_suggestion_cache` | AIレシピのキャッシュ |
| `gemini_daily_usage` / `gemini_user_daily_usage` | Gemini呼び出し回数（アプリ全体・アカウントごとの日次上限用） |

- 初回ログイン時にサーバー側にデータがなければ、このブラウザに残っている前回の内容（同じアカウント）を登録します。なければ空の冷蔵庫から始まります（サンプル食材は画面から入れられます）。食材が空のうちは、起動時のAI提案は行いません。
- 既存のDBは起動時に自動で列が追加されます（冷凍・値段・金額）。
- ブラウザの `localStorage` には、ログイン情報と最後に読み込んだ食材だけを保存します。これはサーバーに接続できないときの読み取り専用表示に使います（オフライン中の変更は保存されません）。
- 別のブラウザやPCからでも、同じバックエンドにつながれば同じデータを使えます。
- **バックアップ**：FastAPIを停止してから `backend/data/mottainai.db` をコピーしてください。DBを削除するとキャッシュも含めて全データが消えます。

### PostgreSQLへの移行について

個人・ローカル利用ではSQLiteで十分です。利用者が増えて同時書き込みが多くなる段階でPostgreSQLを検討します。現状の実装はSQLite専用のため、接続設定だけでは切り替わりません。移行時はDBアクセス層をSQLAlchemy等へ統一し、スキーマとデータを移行する想定です。

## ディレクトリ構成

```text
backend/
├── main.py        # FastAPIの設定・CORS・ルーター登録・/api/health

├── pantry.py      # /api/pantry 食材のCRUD・消費・削除の取り消し・もったいない記録・リセット

├── saved_recipes.py # /api/recipes/saved 保存したレシピの一覧・保存・削除
└── tests/         # pytestによるAPI・照合処理のテスト

frontend/src/
├── App.tsx        # ログイン状態の管理
├── Kitchen.tsx    # ログイン後の画面状態とAPI操作（ログインごとに作り直し、別ユーザーのデータを残さない）
├── components/    # 各画面（冷蔵庫・レシピ・買い物リスト・もったいない記録）とモーダル、ログイン画面
├── hooks/         # useToast（通知表示）、useDismiss（Esc・外側クリックで閉じる）
├── api.ts         # API通信とエラーメッセージの日本語化
├── types.ts       # 型定義
├── data.ts        # 定数・サンプルデータ・アプリ内レシピ（backend/recipes.py と同じ内容を保つ）
├── foodPresets.ts # 食材名から単位・カテゴリ・期限の目安を推測する辞書
├── utils.ts       # 日付計算・食材名の照合（backend/ingredients.py と同じ規則）・レシピ評価・localStorage
└── styles.css     # 全体のスタイル（レスポンシブ対応を含む）
```

見た目はCSSで一元管理し、TSXは表示の構造に専念させています。

### テスト

```bash
cd backend
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
```

フロントエンドのテスト（Vitest。食材名の照合・分量の推測・期限計算・アプリ内レシピの並び順・食材の目安など）：

```bash
cd frontend
npm test          # 1回実行
npm run test:watch  # 変更を監視して再実行
```

GitHubへのpushとプルリクエストでは、GitHub Actions（`.github/workflows/ci.yml`）がバックエンドのテスト、フロントエンドの型チェック・テスト・ビルドを自動で実行します。

バックエンドのテストは一時ディレクトリのSQLiteを使うため、`backend/data/mottainai.db` には影響しません。フロントエンドとバックエンドのアプリ内レシピが一致しているかもテストで確認します。

## 公開（デプロイ）するときの注意

ローカルで使う限り、ホスティング登録や支払いは不要です。インターネットに公開する場合は以下に注意してください。

- **APIキーはバックエンドの環境変数に設定**し、フロントエンドには置かないでください。
- `FRONTEND_ORIGINS` と `VITE_API_BASE_URL` を公開URLに変更してください。
- `DATABASE_PATH` には、再起動・再デプロイ後も残る**永続ストレージ**を指定してください。
- **Render FreeにはSQLiteを置かないでください。** 無料Web Serviceのファイルシステムは一時的で、再起動・スリープ・再デプロイでSQLiteファイルが消えます。Renderの無料PostgreSQLも作成から30日で期限切れになります（[Render Free](https://render.com/docs/free)）。
- 他人にAPIの無料枠を使われないよう、利用制限の値も見直してください。
- ログイン失敗回数・AI提案の間隔／1時間あたりの回数はプロセスのメモリで数えています。**uvicornはワーカー1つ（`--workers` を指定しない）で動かしてください**。複数ワーカーにすると制限がワーカーごとに別々になります（1日の上限はSQLiteで数えるので影響しません）。
- リバースプロキシ（nginx、Render、Fly.io など）の後ろで動かす場合は、接続元IPを正しく取れるよう `uvicorn main:app --proxy-headers --forwarded-allow-ips=<プロキシのIP>` を指定してください。指定しないと全員がプロキシと同じIPに見え、接続元ごとのログイン・新規登録の制限を全員で共有してしまいます。

## トラブルシューティング

| 症状 | 原因と対処 |
| --- | --- |
| 「サーバーに接続できません」 | バックエンドが起動しているか、`VITE_API_BASE_URL` が正しいか確認 |
| `geminiConfigured` が `false` | `backend/.env` の `GEMINI_API_KEY` を確認し、FastAPIを再起動 |
| HTTP 503（混雑） | Gemini側の一時的な混雑。バックエンドが自動で最大3回再試行（約1・2・4秒＋ゆらぎ、`Retry-After` があればそれに従う）。それでも失敗したら少し待って「もう一度提案」 |
| HTTP 429（上限） | Googleの無料枠の上限に到達。日次上限は太平洋時間0時（日本時間16〜17時ごろ）にリセット |
| HTTP 401 / 403 | APIキーやモデルの権限を確認 |
| HTTP 404 | `GEMINI_MODEL` のモデル名を確認 |
| 「AI提案は1人1日○回まで」など | アプリ側の呼び出し制限。時間をおくか、環境変数で調整 |

Gemini APIの稼働状況は[Google AI Studioのステータス](https://aistudio.google.com/status)で確認できます。

## 食品安全について

賞味期限・消費期限だけで食品の安全性を完全に判断することはできません。保存方法や開封状態も確認し、異臭・変色・ぬめりなどの異常があれば食べないでください。肉・魚・卵は十分に加熱してください。アプリのAI提案は食品安全の専門的な判定ではありません。
